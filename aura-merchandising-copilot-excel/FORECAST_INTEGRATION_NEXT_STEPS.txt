AURA MERCHANDISING COPILOT — FORECAST-INTEGRATED OPTIMIZER UPDATE

What changed:
- app/main.py: POST /api/optimize now uses the SKU forecast's average daily demand when forecast generation succeeds.
- app/main.py: POST /api/chat receives the same forecast context and source.
- If forecasting cannot run (for example, insufficient history), the endpoint falls back to the recent 30-day sales rate and reports the source.
- The forecast horizon is capped at 90 days; for longer optimization deadlines, the 90-day average daily forecast is used.
- The promotion uplift multipliers remain heuristic assumptions. The forecasting model does NOT learn causal promotion effects.
- Existing /api/forecast, /api/products, /api/brands, /api/dead-stock endpoints remain in place.

How to apply:
1. Back up your existing project folder.
2. Extract this ZIP into a new folder.
3. Keep your own .env file and API keys secure. This ZIP intentionally excludes .env and .venv.
4. Activate your existing virtual environment. Install dependencies from requirements.txt if needed.
5. Run: uvicorn app.main:app --reload
6. Open http://127.0.0.1:8000/docs
7. Test POST /api/optimize with:
   {
     "sku": "AE-POLO-001",
     "deadline_days": 30,
     "objective": "balanced",
     "minimum_margin_percent": 20,
     "max_discount_percent": 30
   }
8. Check baseline_demand_source, forecast_summary, feasible_scenarios_count,
   recommendation.meets_deadline and recommendation.meets_minimum_margin.

Validation:
- 6 pytest tests passed.
- API smoke test: POST /api/optimize returned HTTP 200 and baseline_demand_source=forecast_model.
- For AE-POLO-001 the forecast baseline was approximately 1.05 expected units/day in the supplied synthetic demo workbook.

Caveat:
Forecast WAPE is still high on the small synthetic dataset. Review evaluation metrics and validate forecasts on representative data before operational use.
